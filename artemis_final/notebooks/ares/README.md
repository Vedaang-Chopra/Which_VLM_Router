# VLM Evaluation Pipeline

This directory contains the notebooks and documentation for the **Artemis VLM Evaluation Pipeline**. The core component is `02_eval_scoring.ipynb`, which orchestrates the scoring of model responses using a combination of static metrics, text-based LLM judges (Glider), and visual VLM judges (Llama-4-Scout).

## 🚀 Overview

The evaluation pipeline is designed to be **robust, parallel, and resumable**. It processes responses stored in the PostgreSQL database effectively "grading" the VLM outputs on multiple dimensions:

1.  **Correctness**: Is the answer factually correct based on the Ground Truth?
2.  **Reasoning**: Does the model provide sound reasoning?
3.  **Visual Grounding**: Is the answer derived from the image content?
4.  **Confidence**: How confident is the model in its own answer?

## 📊 Evaluation Metrics & Formulas

We employ a tiered evaluation strategy, moving from cheap deterministic checks to expensive model-based judgements.

### 1. Static Metrics (Deterministic)
*Implemented in `ares.evaluation.evaluation.Scorer`*

These metrics define "correctness" for standard benchmarks.

| Metric | Database Column | Formula / Logic |
| :--- | :--- | :--- |
| **Exact Match** | `score_exact_match` | `1.0` if `pred.strip().lower() == gt.strip().lower()`, else `0.0` |
| **Exact Match (Norm)** | `score_exact_match_normalized` | Same as above, but after **normalization**: removes articles ("a", "an", "the"), punctuation, and extra whitespace. |
| **F1 Score** | `score_f1` | Standard token-level F1 score calculated on normalized text sets `P` (prediction) and `G` (ground truth). <br> $F1 = 2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}$ |
| **Contains GT** | `score_contains_gt` | `1.0` if the normalized Ground Truth is a substring of the normalized Prediction. |
| **Numeric Match** | `score_numeric_match` | Extracts first valid number from Pred and GT. `1.0` if $\frac{\|pred - gt\|}{\|gt\|} \le 0.01$ (1% tolerance), else `0.0`. |
| **MC Letter Match** | `score_mc_letter_match` | Extracts multiple-choice letter (A-D) using Regex. `1.0` if `pred_letter == gt_letter`, else `0.0`. |
| **Refusal** | `is_refusal` | Boolean. True if response contains phrases like "I cannot", "I apologize", "I am unable". |

#### 🏆 "Is Correct" Logic
The final `is_correct` boolean is derived based on the **Ground Truth Type**:
-   **Numeric**: `score_numeric_match >= 0.99`
-   **Multiple Choice (MC)**: `score_mc_letter_match >= 0.99`
-   **Freeform**: `score_f1 >= 0.5`
-   **Default**: `score_exact_match_normalized >= 0.99` OR `score_contains_gt >= 0.99`

---

### 2. Confidence Estimation
*Implemented in `ares.evaluation.confidence`*

We estimate how confident the model is in its answer to detect hallucinations.

| Metric | Database Column | Formula / Logic |
| :--- | :--- | :--- |
| **Confidence Score** | `confidence_score` | **Choice A (Logprobs)**: Mean probability of generated tokens (excluding special tokens). <br> **Choice B (Heuristic)**: Base `0.7`. Penalty `-0.2` for uncertainty words ("I think", "maybe"). Bonus `+0.1` for brevity (<10 words). Clamped $[0.0, 1.0]$. |
| **Source** | `confidence_source` | `'logprobs'` or `'heuristic'` |

---

### 3. Glider (Text-Only Judge)
*Implemented in `ares.evaluation.evaluation.GliderEvaluator`*

Evaluates reasoning quality using `PatronusAI/glider` (Llama-3 based judge).

| Metric | Database Column | Description |
| :--- | :--- | :--- |
| **Glider Score** | `glider_score` | **0.0 - 1.0** score indicating answer quality and consistency with Ground Truth. |
| **Reasoning** | `glider_reasoning` | Text explanation of the score generated by Glider. |

---

### 4. VLM Judge (Visual + Listwise Ranking)
*Implemented in `ares.evaluation.judge_molmo.VLMJudge`*

Uses `nvidia/Llama-4-Scout-17B` (or similar VLM) to visually verify answers. It uses a **Listwise Ranking** approach: provided with the Image, Question, Ground Truth, and *multiple* anonymized model answers, it ranks them.

| Metric | Database Column | Description |
| :--- | :--- | :--- |
| **VLM Score** | `judge_molmo_score` | **0 - 10** score assigned by the VLM. (10=Perfect, 0=Wrong/Hallucinated). |
| **Rank Group** | `judge_molmo_rank_group` | Integer ranking (1=Best group). Ties are allowed. |
| **Raw Output** | `judge_molmo_raw` | Full raw JSON output from the judge for debugging. |

## 🗄️ Database Saving & Schema

Data flows from the `RouterEvalPipeline` into PostgreSQL using `ares.db.operations`.

### Table: `vlm_responses`
Stores the model outputs and primary metrics.

```sql
CREATE TABLE vlm_responses (
    sample_id UUID,
    model_name TEXT,
    response_raw TEXT,              -- The actual model text output
    latency_ms INTEGER,             -- Total generation time
    confidence_score FLOAT,         -- [0.0, 1.0]
    score_exact_match FLOAT,        -- [0.0, 1.0]
    score_f1 FLOAT,                 -- [0.0, 1.0]
    is_correct BOOLEAN,             -- Derived "Final Answer" status
    is_refusal BOOLEAN,
    estimated_cost_usd FLOAT,       -- Cost of this specific interference
    gpu_util_percent FLOAT,         -- GPU utilization snapshot
    ...
    PRIMARY KEY (sample_id, model_name)
);
```

### Table: `vlm_evaluations`
Stores expensive, asynchronous judge evaluations.

```sql
CREATE TABLE vlm_evaluations (
    sample_id UUID,
    model_name TEXT,
    glider_score FLOAT,             -- 0.0 - 1.0
    glider_reasoning TEXT,
    judge_molmo_score FLOAT,        -- 0.0 - 10.0
    judge_molmo_rank_group INT,     -- 1, 2, 3...
    created_at TIMESTAMP DEFAULT NOW(),
    PRIMARY KEY (sample_id, model_name)
);
```

## ⚙️ Configuration & Execution

### Prerequisites
Ensure your vLLM endpoints are running:
-   **Glider**: Ports `8805`, `8807`
-   **VLM Judge**: Ports `8806`, `8808`

### Running the Notebook (`02_eval_scoring.ipynb`)

1.  **Initialize Pipeline**:
    The notebook initializes `RouterEvalPipeline` with the database connection and endpoint configurations.

    ```python
    pipeline = RouterEvalPipeline(
        engine=engine,
        runner=runner,
        glider_model_names=["glider-1", "glider-2"],
        vlm_judge_model_names=["vlm-judge-1", "vlm-judge-2"],
        tracker_path="eval_progress.json"
    )
    ```

2.  **Execute Evaluation**:
    Call `pipeline.evaluate_all()` to process all pending samples.
    -   **`force=False`**: Skips already evaluated samples (Incremental mode).
    -   **`force=True`**: Re-evaluates everything.

3.  **Progress Tracking**:
    The pipeline maintains a local file `eval_progress.json` to track batch completion. If the notebook crashes, simply restart it, and it will resume from the last saved batch.
